> **Superseded artefact — added to this file after the fact, by hand.**
>
> This pair of files was produced by an earlier version of the harness and the
> runner that would write them today does not exist any more. Specifically:
>
> - The JSON carries `latencyMs.max` for a figure that is really **p99.99**.
>   The field has since been renamed `p9999`, because calling a tail percentile
>   a maximum overstates it in every artefact that carried the old name. Read
>   the `max` column below as p99.99.
> - There is no `worst` run recorded, so the gate that now refuses a throughput
>   when the *worst* of the runs shed requests was not applied to it.

>   on the wire.
> - It was run with a single sweep, before the harness swept the app list in
>   both directions — and it was a single-app run, so it has no queue position
>   to compare against anyway.
> - The working tree was **dirty** when it was captured, so the code measured is
>   not exactly the commit named below.
> - It is `"schema": 1`; the current runner writes `"schema": 2`.
>
> It is kept, unmodified apart from this banner, because deleting the evidence
> that the format changed would be worse than labelling it. It is a format
> sample. Do not quote a number from it.

## memory per concurrent connection  `GET /api/events`

RSS of the whole process tree at idle, then holding N open SSE connections, and the delta divided by N. This is the number a Go runtime is supposed to win, so it is the number we are most obliged to measure honestly.

| app | RSS idle | RSS holding N | connections held | delta | **per connection** | trustworthy |
| --- | ---: | ---: | ---: | ---: | ---: | :-: |
| borgo | 93.6 MiB | 157.9 MiB | 1000 | 64.3 MiB | **65.8 kiB** | yes |

RSS is the resident set of the *whole process tree* (for borgo: the Bun front server plus the Go API binary). Absolute RSS says more about an allocator's growth policy than about a framework; the delta per connection is the comparable figure, and even it is a lower bound, since neither runtime returns freed pages to the OS promptly.
